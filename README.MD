# DouyinLiveTool — 抖音直播监控 + 弹幕捕获

实时捕获抖音直播间弹幕、礼物、点赞、进场等消息，支持直播流播放，深色主题 GUI。

## 功能

- **主播管理** — 添加/删除主播，自动获取昵称，列表持久化
- **一键检测** — 批量检测所有主播开播状态
- **持续监控** — 按主播设置定时检测，开播自动播放或录制，连续两次确认下播后停止录像
- **多主播消息采集** — 可选开播自动采集弹幕、礼物等消息，独立连接与存档，心跳超时和断线重连
- **直播录制** — FFmpeg 无转码保存 MKV，可与 PotPlayer 同时观看，支持手动开始和停止
- **12 种消息类型** — 弹幕 / 礼物 / 点赞 / 进场 / 关注 / 粉丝团 / 表情 / 观看统计 / 房间信息 / 直播统计 / 流适配 / 下播状态
- **消息过滤** — 复选框开关，即时隐藏/显示各类消息
- **数据存档** — 自动保存为 JSONL，按主播 + 日期分文件
- **直播流播放** — 提取多清晰度直链，一键 PotPlayer 播放
- **Cookie 配置** — 登录后获取礼物等完整消息

## 环境要求

- Windows 10 / 11
- Python 3.7+
- Node.js（mini_racer 依赖）
- FFmpeg（仅录制需要）；PotPlayer（仅观看需要）

## 安装

```bash
git clone https://github.com/eplayn/DouyinLiveMonitor.git
cd DouyinLiveMonitor
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> ```

## 使用

```bash
python main.py                    # 启动 GUI
python main.py <直播间ID>          # 选中指定直播间，采集需开启监控
```

### 配置 Cookie（获取礼物消息和直播流）

1. 浏览器打开 https://live.douyin.com 并登录
2. F12 → 控制台 → 输入 `document.cookie` 回车
3. 复制完整结果
4. 在 GUI 中点击 **Cookie** 按钮 → 粘贴 → 保存

### 持续监控与录制

1. 添加主播，在监控列表选择需要的主播，勾选 **将选中主播加入持续监控**。所有未配置的主播默认不参与监控，勾选后立即保存；列表的“监控名单”列显示已加入或未加入。
2. 设置检测间隔（默认 60 秒，范围 15–3600 秒）、录像目录及播放器路径。
3. 从设置中的主播下拉框逐一选择主播，勾选 **持续监控此主播**，再按需勾选 **开播自动打开 PotPlayer**、**开播自动使用 FFmpeg 录制**、**开播自动采集弹幕、礼物等消息**，然后保存。
4. 点击 **启动监控**。启动时已经开播的主播也会执行所选动作；同一场直播不会反复打开播放器。

持续监控、自动播放、自动录制和自动消息采集默认关闭；每次启动程序后需要手动启动监控。只轮询明确加入监控名单的主播；未选择任何主播时会提示先选择。监控列表显示各主播最近检测时间、直播状态、消息采集状态和录制状态，不会切换当前查看的主播。取消某位主播的监控后，不再对其定时检测或执行新的自动操作，消息采集及重连停止；已有播放和录像继续，可单独点击“停止录制”。点击主播只选择查看对象并检测一次直播状态，不启动消息采集。

录制需要 FFmpeg，可自行安装后在设置中选择 `ffmpeg.exe`，也可使用：

```powershell
winget install --id Gyan.FFmpeg --exact
```

程序会从 PATH、项目的 `.tools/ffmpeg/ffmpeg.exe` 和 WinGet 用户链接目录查找 FFmpeg；查找失败时请填写完整路径。PotPlayer 也支持填写自定义安装路径。`.tools/` 中的本机工具不提交到 Git。

- **开始录制 / 停止录制**：先在监控列表选择主播。手动开始需要已有直播流，可先一键检测。手动停止后，本场直播不会再次自动录制；再次点击开始录制可恢复。
- **停止监控**：停止后续检测、所有消息采集及重连，现有录像和播放继续。停止监控期间不再自动判断下播或重启录制。
- **退出程序**：若仍有录像，会询问是否停止录像并退出；程序发送正常停止指令并等待文件收尾，超时才强制结束自己启动的录制进程。不会关闭 PotPlayer。
- 网络错误和异常接口响应显示为检测失败，不当作下播；连续两次明确未开播才结束录制。录制进程中断后，监控开启且仍在直播时至少间隔 60 秒再重试。
- **录制停滞恢复**：每 2 秒读取 FFmpeg 输出进度，并检查文件大小；两者连续 60 秒都无进展时发送正常停止指令，10 秒仍未退出才强制结束。自动录制开启且监控继续时，至少延迟 60 秒重新检测开播状态，使用新的流地址和新的文件开始下一段；检测失败、确认下播、取消监控或手动停止后不会自动重启。原录像保留，停滞期间缺失的视频无法补回。
- 同时录制多位主播，录像分别保存到 `recordings/主播名（ID）/日期_时间.mkv`。要填充对应消息文件，需同时开启该主播的自动录制和自动消息采集。同名 `.jsonl` 保存视频录制时间内收到的弹幕、礼物等消息；`.ffmpeg.log` 单独保存 FFmpeg 诊断信息。自定义录像目录可在设置中指定。
- PotPlayer 和 FFmpeg 分别读取直播流，同时观看并录制通常需要两路下载带宽。录制使用 `-c copy`，不重新编码。

**PotPlayer 录制说明：** 本次自动录制由 FFmpeg 完成，未启用无法可靠确认状态的 PotPlayer 自动录制控制。若希望用 PotPlayer 自身保存流，可在播放器内按 `Ctrl+A` 配置，按 `Ctrl+Shift+A` 开始或停止；这种手动录像不由本程序管理。`/cap` 不是自动保存直播流参数。

### 消息采集与心跳

消息采集必须同时满足：已启动监控、主播已加入监控名单、该主播已开启“开播自动采集弹幕、礼物等消息”，并检测到开播。各主播独立采集并存档，即使未打开播放器或没有视频流地址也可以采集。点击或切换主播、单次检测以及播放操作均不会启动消息采集；取消主播监控或关闭自动采集会停止其消息连接及重连。控制台显式执行 `python main.py console <ID>` 仍单独采集指定直播间，不使用 GUI 的监控配置。

消息区实时显示所有采集中的主播，无需手动选中主播，每条消息标注 `[主播名（直播间ID）]`，切换主播不会清空已有消息。下方“弹幕、礼物、点赞、进场、关注、粉丝团、表情”勾选框统一控制这些类型的显示，默认只勾选弹幕；不勾选仍会采集、存档。下播状态和系统提示单独显示；观看统计更新当前选中主播的观看人数，房间信息、直播统计和流适配仅存档，避免刷屏。排行榜消息当前未启用解析。

收到并成功解析的消息按直播场次写入 `data/主播名（ID）/room_平台场次ID.jsonl`，每行一条，按接收顺序追加，不按平台消息时间重新排序；录制期间收到的消息也会同步写到对应视频的同名 `.jsonl` 文件。这里的场次 ID 是平台实际 `room_id`，与主播主页的直播间 ID 区分。同一场跨午夜、断线重连、暂停后恢复采集均续写同一文件；程序重启后重新开启监控，获取到相同场次 ID 时也会续写。新的平台场次 ID 使用新文件，即使两场之间的下播未被轮询捕捉也能区分。旧连接排队中的消息仍归旧场文件。

每条记录包含 `rid`、`session_id`、`received_at`（本机接收日期时间）、`time`（消息时分秒，无效时使用本机时间）、`type` 和 `text`。消息区会打印本场存档路径，下方显示过滤不影响存档。若检测接口和消息连接均无法提供有效场次 ID，会使用 `local_采集开始时间_唯一编号.jsonl` 并提示；此时同次程序运行中的重连继续写原文件，确认下播后另建文件，重启后也新建文件，避免误合并不同场次。旧版按日期保存的文件保留原样，不自动拆分或迁移。

存档失败会提示，不会静默忽略。消息是否能收到取决于服务器推送和 Cookie 状态，不代表可以获取平台所有事件；暂停或断线期间未收到的消息不会自动补齐。

每个消息连接每 5 秒发送 WebSocket Ping，并检查 4 秒内的 Pong 响应；服务器要求确认时仍回复 ACK。连接断开后，只要采集仍被需要就延迟 30 秒重连。明确收到下播消息或监控确认下播后停止连接。没有弹幕不等于连接失效，不以聊天消息数量判断心跳。FFmpeg 录制通过持续读取媒体数据和进度检查维护，不发送弹幕心跳。

## 项目结构

```
├── main.py               # 入口
├── chat_window.py         # GUI 窗口
├── monitoring.py          # 定时检测、播放与录制进程管理
├── message_collector.py   # 多主播消息连接、归属与重连管理
├── monitor_panel.py       # 监控列表与设置界面
├── liveMan.py             # WebSocket 弹幕引擎
├── sign.js                # WebSocket 签名
├── protobuf/
│   ├── douyin.proto       # 协议定义
│   ├── douyin.py          # 生成的 Python 类
│   └── __init__.py
├── requirements.txt
└── .gitignore
```

## 开发说明

运行监控逻辑和 Tk 界面回归测试（需要可用的桌面会话）：

```bash
python -m unittest discover -s tests -v
```

`protobuf/douyin.proto` 是协议定义源文件，`douyin.py` 已由 protoc 编译生成，**运行时不需要 protoc**。如需重新生成：

```bash
pip install protoc
protoc -I protobuf --python_betterproto_out=protobuf protobuf/douyin.proto
```

## 数据格式

存档在 `data/主播名（ID）/日期.jsonl`，每行一条：

```json
{"time": "21:17:40", "type": "chat", "text": "【弹幕】 用户: 内容"}
{"time": "21:17:42", "type": "gift", "text": "【礼物】 用户 送出 小心心 x10"}
```
